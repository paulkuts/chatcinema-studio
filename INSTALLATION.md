# Установка на Windows 11

## Требования

- Windows 11 x64; проверка выполнена на одной машине Windows x64, отдельная машина пока не проверялась.
- Node.js 24.15.0 и npm 11.12.1. Версия Node записана в `.node-version`; файл сам по себе Node не устанавливает. Установите нужную версию из [официального архива Node.js](https://nodejs.org/en/download/archive/v24.15.0), после чего откройте новое окно PowerShell и проверьте `node --version` и `npm --version`.
- Интернет для npm registry и, при первом рендере, загрузки Chrome Headless Shell с серверов Remotion/Google. На Windows x64 проверенная копия загрузила браузер в `node_modules/.remotion/`. Доступность загрузки на другой машине не проверена.
- Свободное место для пакетов, браузера, временных файлов и MP4. На этой машине Remotion установил FFmpeg и ffprobe в `node_modules/@remotion/compositor-win32-x64-msvc/`; отдельная установка FFmpeg для рендера не потребовалась. Для независимой диагностики подходит полноценный ffprobe из FFmpeg.

## Установка

Получите полную копию репозитория с `package-lock.json` и расположите на диске D:, например `D:\Codex_Projects\ChatCinema_Studio`. Не переносите `node_modules` с другой машины. В PowerShell:

```powershell
cd D:\Codex_Projects\ChatCinema_Studio
node --version
npm --version
npm ci
npm run typecheck
npm test
npm run build
npm run dev
```

Откройте адрес из консоли, обычно http://127.0.0.1:4173. Сервер нужно запускать из корня проекта: пути данных, ресурсов и композиции относительны текущему каталогу. Если порт 4173 или 24678 занят, в том же окне задайте до запуска:

```powershell
$env:CHATCINEMA_PORT='4174'
$env:CHATCINEMA_HMR_PORT='24679'
npm run dev
```

Тогда откройте http://127.0.0.1:4174. Переменные действуют в текущем окне PowerShell. Остановите сервер Ctrl+C. `npm run build` собирает клиент, а `npm run dev` запускает локальный сервер из исходников; отдельного production-сервера и установщика пока нет.

## Проверка

Создайте персонажа и сообщение, запустите предпросмотр, нажмите «Сохранить», затем «Export MP4». Дождитесь пути к файлу в нижней строке; первый рендер может скачивать браузер. Повторите экспорт того же проекта. На Windows x64 установленный Remotion ffprobe можно вызвать так, подставив путь из приложения:

```powershell
& .\node_modules\@remotion\compositor-win32-x64-msvc\ffprobe.exe -v error -show_entries 'format=duration:stream=codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels' -of json 'D:\путь\к\export.mp4'
```

Для проверенного тестового проекта результат: H.264 1080×1920, 30 fps, AAC 48000 Гц, 2 канала, 2,005 с. Длительность и звук зависят от проекта. При ошибке загрузки браузера проверьте доступ к интернету и сообщение приложения; не считайте установку полностью проверенной до успешного экспорта.

## Данные и перенос

`data/projects/<id>/project.json` содержит проект, `exports/` — его MP4. Перед обновлением сделайте резервную копию `data/projects` за пределами заменяемой папки приложения. Для переноса скопируйте папку нужного `<id>` в `data/projects` другой установки той же версии, сохранив ID каталога; перезапустите приложение и откройте проект через список. Звуки не вложены в проект: нужны соответствующие файлы `public/sfx/` той же версии приложения; Arial зависит от системы. Реальный перенос и рендер на другом компьютере пока не проверены.

Не публикуйте и не распространяйте встроенные WAV до проверки прав; см. [LICENSES.md](LICENSES.md). Условия Remotion и транзитивных пакетов также необходимо проверить для предполагаемого применения.
